# 下棋（围棋先做，以后加中国象棋、国际象棋、跳棋）

儿子下 19 路围棋，业余 3 级左右（考过几次级）。用女儿那台 pad 上的小新，不单开账号。
不用更新 APK：棋盘、复盘、设置都是网页，部署 gpu2 就生效。

## 1. 用法

| 孩子说 / 点 | 小新做什么 |
|---|---|
| 「陪我下围棋」「来一盘」「和你下棋」 | 弹「开一盘」卡片（档位、执黑执白、让子），点开始进全屏棋盘 |
| 「用 1 段陪我下」「和世界冠军下一盘」 | 直接按这个档位开 |
| 棋盘上：落子 / 悔棋 / 提示 / 认输 / 数子 | 见第 4 节 |
| 「看看我最近围棋胜率」「最近下得怎么样」 | 弹看板：总胜率、按档位胜率、最近几盘、坏棋数走势 |
| 「复盘一下昨天那盘」「复盘刚才那盘」 | 那天只有一盘直接打开；好几盘就列出来让他点 |

## 2. 档位（设置里能改默认，每盘开始也能选）

| 档位 | 怎么下 |
|---|---|
| 世界冠军 | 主模型 b28，每步搜 3000 次（A100 约 4 秒），取最佳点 |
| 中国冠军 | 主模型 b28，每步搜 1500 次（约 2 秒），取最佳点 |
| 9 段 … 1 段、1 级 … 20 级 | 人类模型 b18-humanv0，`humanSLProfile = rank_<档>`，按人类策略随机落子 |

人类档的落子方法（照 KataGo 文档的 Human SL 指南）：带 `ignorePreRootHistory=false` 搜 ~60 次；
最佳点是 pass 就 pass，否则按 `humanPolicy` 去掉 pass 后按概率抽一个。
不加「搜索修正」：加了会比标的档位强很多，孩子选 3 级却碰上 1 段。

## 3. 架构

```
┌────────────── pad（小新网页，全屏） ───────────────┐
│ static/go.js   棋盘（canvas）、落子、悔棋、提示、胜率条    │
│ static/goreview.js  复盘：胜率曲线 + 棋盘 + 关键步 + 讲解  │
│ static/gostats.js   看板                               │
└───────────────┬─────────────────────────────────┘
                │ HTTP：/api/go/*   （聊天里的工具也能开局、出看板、开复盘）
┌───────────────▼──────────── gpu2 小新服务（8184）─────────────┐
│ server/games/__init__.py   棋种登记表（go；以后 xiangqi、chess…）     │
│ server/games/go_rules.py   19 路规则：提子、劫、禁入点、数子（中国规则）│
│ server/games/go.py         对局：开局、落子、引擎应手、悔棋、存档、结果 │
│ server/games/go_review.py  复盘：关键步、代码算的事实、讲解+校验        │
│ server/games/katago.py     常驻 KataGo analysis 进程（JSON 行协议）    │
│ server/tools/games.py      小新的工具：play_go / go_stats / go_review  │
└───────────────┬──────────────────────────────────────────────┘
                │ stdin/stdout JSON
┌───────────────▼──────── /Data/cmbian/katago ────────┐
│ katago v1.18.2 CUDA 12.8 + cudalibs/（cuBLAS、cuDNN） │
│ main.bin.gz  b28c512nbt（最强公开网络）               │
│ human.bin.gz b18c384nbt-humanv0（模仿人类各档）        │
└──────────────────────────────────────────────────┘
```

- KataGo 常驻：服务启动时拉起，显存约 2 GB，空闲不占算力。挂了自动重启；起不来时棋盘提示「小新的棋盘大脑没起来」，不卡别的功能。
- 每一步（双方）都分析一次：胜率、目差、最佳点、后续变化（PV）、每个点的归属。存在棋谱里，复盘不用再算。
  孩子下完一步，这次分析和小新的应手并行（小新按档位落子，分析统一用主模型 400 次）。
- 存档：`XIAOXIN_DATA/games/go/<id>.json`，一盘一个文件，含档位、执色、贴目、每步坐标、每步分析、结果。

## 4. 对局界面（全屏，盖住聊天）

- 顶部：对手档位、执色、手数、提子数，「胜率条」（黑白两色，可在设置里关掉，正式练习时不看）。
- 中间：19 路棋盘，星位、坐标，最后一手标记。手指点一下出「预落子」虚影，再点同一点才落（防误触，pad 上手指粗）。
- 底部按钮：悔棋（设置里可关）、提示（标出 AI 推荐的 3 个点，可关）、停一手、认输、数子结束。
- 小新思考时显示「小新在想…」，不能落子。
- 双方连续停一手 → 中国规则数子，判胜负；认输直接结束。结束后出「这盘复盘一下吗？」。
- 中途退出（关页面、刷新）：对局存着，再进「下棋」继续这一盘。

## 5. 复盘

```
┌ 胜率曲线（横轴手数，竖轴孩子的胜率，关键步红点） ┐
├ 棋盘（可前后翻，点曲线 / 关键步直接跳）           ┤
│   你下的点 ●，AI 建议的点 ◎，「看 AI 的下法」逐步摆 │
├ 这一步：第 47 手 你下 Q16，AI 建议 R14            ┤
│   胜率 62% → 31%，目差 黑 +3 → 白 +5               │
│   讲解：……                                       │
└ 关键步列表：47 手 -31%，88 手 -22%，130 手 -18% ┘
```

### 关键步怎么挑（纯数字）
- 每步算「孩子那一方」在这步前后的胜率差和目差差（前：轮到他下之前的分析；后：他下完之后的分析）。
- 失误分级：胜率掉 ≥ 20% 或目差掉 ≥ 8 目 = 大失误；≥ 10% 或 ≥ 4 目 = 失误。
- 胜负已定时（他的胜率 < 5% 或 > 95%）胜率不怎么动，只按目差算。
- 一盘取最多 5 个关键步，按损失从大到小。

### 讲解里的事实全由代码算（`go_review.facts`）
| 事实 | 怎么算 | 准不准 |
|---|---|---|
| 某块棋几口气、被叫吃 | 规则代码数气 | 100% |
| 下一手能提几颗 | 在 AI 的 PV 里实际走，数提子 | 100%（是 AI 的变化，不是必然） |
| 这步之后 AI 变化里会被吃多少 | PV 前 6 手实际走，数提子 | 同上 |
| 某块棋死了 / 危险 | 归属预测：这块棋所有子平均 ≥ 0.75 归对方 = 「很可能被吃」；0.4–0.75 = 「危险」 | KataGo 判断，业余棋几乎不错 |
| 某片地归属变了 | 前后归属预测相减，变了 ≥ 1.2 的点连成片，数点数，按角/边/中腹说位置 | 同上 |
| 目差、胜率 | 直接用分析结果 | 准 |
| AI 建议的下法 | PV 前 6 手 | 准（是 AI 的看法） |

### 讲解由大模型说，但先校验
- 给模型的只有上面的事实（文字），要它用三年级能听懂的话说 2–4 句，不准加新的变化和棋理。
- 校验：讲解里出现的坐标（A1–T19）、数字（几颗、几目、百分比）必须都在事实里出现过；不在就带着错误再让它改一次，还不行用模板句（按事实拼的固定说法）。
- 讲解存进棋谱，下次打开不再生成。

## 6. 看板（「看看我最近围棋胜率」）
- 卡片：总盘数、胜/负、胜率；按档位分组的胜率（例如「对 3 级 5 胜 3 负」）。
- 最近 10 盘：日期、档位、执色、结果（几目 / 中盘胜）、手数、大失误几步；点一盘开复盘。
- 走势：每盘「平均每手损失目数」折线（越低越好），比单看输赢更能看出进步。

## 7. 设置 → 下棋（一级页），里面「围棋」是二级

| 项 | 默认 | 说明 |
|---|---|---|
| 默认档位 | 2 级 | 比他 3 级略强一点 |
| 默认执色 | 黑 | |
| 贴目 | 7.5 | 中国规则；让子棋自动 0.5 |
| 让子 | 0 | 0–9 |
| 允许悔棋 | 开 | |
| 允许提示 | 开 | |
| 对局中显示胜率条 | 开 | |
| 下坏了提醒一句 | 关 | 开了：大失误后小新说「再想想？」并允许悔一步 |
| KataGo 状态 | — | 在不在线、GPU、显存、最近一次落子用时 |

以后加棋种：同一页上面加二级标签「中国象棋」「国际象棋」…，每个棋种在 `server/games/` 下登记自己的引擎和规则。

## 8. 测试用例（先写好，做完逐条过）

### 8.1 规则（单元测试，`tests/test_go_rules.py`）
- R1 提一子：白子四面被黑围住，黑落最后一口气 → 白子被提，黑提子数 +1。
- R2 提一块：3 子白棋只剩 1 气 → 一手提 3 颗。
- R3 禁入点：落下后自己没气又提不了对方 → 拒绝（「这里不能下，没有气」）。
- R4 落下后自己没气但能提对方 → 允许（先提后算气）。
- R5 打劫：刚被提劫，立刻提回 → 拒绝（「打劫，要先在别处下一手」）；隔一手后可以提。
- R6 已有子的点、棋盘外的点 → 拒绝。
- R7 停一手：双方连续停 → 对局结束进入数子。
- R8 数子（中国规则）：构造终局盘面，子 + 空，贴 7.5，结果与手算一致。
- R9 让子：让 4 子，黑预置四个星位，白先下，贴目 0.5。
- R10 悔棋：退两手（孩子一手 + 小新一手），盘面、提子数、劫的状态都恢复。
- R11 坐标：A1–T19 无 I，和 KataGo 的坐标互转一致（随机 1000 点往返）。

### 8.2 引擎（`tests/test_go_engine.py` 用假引擎；`--live` 打真 KataGo）
- E1 人类档按 humanPolicy 抽子，从不选非法点、不选 pass（除非最佳点是 pass）。
- E2 冠军档取 moveInfos[0]。
- E3 引擎挂掉 → 自动重启一次；还不行，接口返回明确错误，界面提示，不卡死。
- E4 并发：两个请求同时来，结果不串（按 id 对应）。
- E5 live：rank_3k / rank_1d / 世界冠军 / 中国冠军 各下一步，记录用时（人类档 < 1 s，中国冠军 < 3 s，世界冠军 < 6 s）。
- E6 live 棋力区分：rank_3k 对 rank_1d 自对弈 10 盘（每盘 ~200 手），1 段应明显多胜；rank_3k 对 rank_3k 应接近五五。
- E7 live：rank_3k 自对弈的大失误率（每盘大失误几步）应明显多于 rank_5d，用来证明「3 级」像 3 级。

### 8.3 复盘（`tests/test_go_review.py`）
- V1 关键步：构造分析序列（胜率 0.6→0.3 那一步）→ 被选为关键步，损失数字对。
- V2 胜负已定时只按目差：胜率 0.02→0.01 但目差 -10→-25 → 算大失误。
- V3 事实「只剩 1 气」：构造盘面 → facts 里有那块的坐标和子数。
- V4 事实「下一手被提 N 颗」：PV 第一手提子 → facts 写对颗数。
- V5 归属变化：前后 ownership 构造右上一片翻转 → facts 写「右上角」和点数。
- V6 校验：讲解里编了一个不存在的坐标 → 被打回；改后通过 / 两次不过用模板句。
- V7 校验：讲解里的数字（「6 颗」）和事实（5 颗）不符 → 打回。
- V8 讲解缓存：第二次打开不再调模型。

### 8.4 复盘话术（live，真 KataGo + 真模型，人工逐条核对）
- T1 拿 3 级档自对弈的 3 盘，每盘取全部关键步（约 15 步），逐条核对：讲解里每句话能在事实里找到出处；没有「为了 / 因为」这类编出来的因果。
- T2 故意坏棋：在一盘正常棋局里替换 3 手（自填一口气、放弃被叫吃的大块、下在已经活透的地方），复盘必须把这 3 手都挑出来，讲解说中要点。
- T3 讲给三年级：不用「厚薄」「味道」「本手」这类术语，或用了要马上解释；每段 ≤ 4 句。
- T4 输棋的整盘总结：「这盘主要输在 47 手和 88 手」，和关键步一致。

### 8.5 接口与界面（`tests/test_go_api.py` + 浏览器手测，pad 分辨率 1280×800 横竖屏）
- U1 开局 → 落子 → 小新应手 → 盘面同步；非法点有提示。
- U2 刷新页面 → 回到同一盘、同一手。
- U3 悔棋 / 提示 / 停一手 / 认输 / 数子 每个按钮都走一遍；设置里关掉悔棋、提示后按钮消失。
- U4 小新思考中点棋盘 → 不落子。
- U5 预落子：点一下出虚影，点别处换位置，再点同一处才落。
- U6 胜率条开关。
- U7 聊天里「陪我下围棋」→ 卡片 → 开始 → 全屏；「看看我最近围棋胜率」→ 看板；「复盘一下昨天那盘」→ 列表 / 直接打开。
- U8 家长 pad 不弹全屏棋盘（和练习模式一样只在孩子的 pad 上）；家长能看看板和复盘。
- U9 pad 实机（插上后）：手指落子准不准、棋盘大小、横竖屏切换后棋盘不变形。

## 9. 实测记录（2026-11-04，gpu2 A100 + 真 KataGo + 真模型）

- 引擎：KataGo v1.18.2 CUDA 12.8；cuBLAS / cuDNN 用 pip 装进 `/Data/cmbian/katago/cudalibs`（系统没装）。启动 ~9 秒，benchmark 约 1400 visits/s。
- 棋力区分（E6/E7，人类模型自对弈各 10 盘、200 手后主模型判胜负）：1 段对 3 级 10:0，3 级对 3 级 6:4，3 级对 10 级 10:0。
- 一手往返（孩子落子 → 小新应完 → 两次分析都好）：3 级 ~1 秒，中国冠军 ~1.5 秒，世界冠军 ~2 秒；真接口实测平均 1.96 秒。
- 复盘：5 个关键步讲解并行生成 ~14 秒，之后缓存。
- 话术（T1–T4）：3 级自对弈插 3 手坏棋（41 / 71 / 101 手，都下在一线角上）+ 3 级对 1 段、孩子执白各一盘，共 17 个关键步逐条核对。
  过程中改掉的问题：
  1. 把整串 AI 变化给模型 → 模型把对方的手说成「你接着下」：变化不再给模型，只给代码在变化里数出来的提子。
  2. 「AI 预计小新会下 X」→ 模型说成「被我抢先下了」：改成「AI 认为小新最好的应手是 X，小新实际下的是 Y」。
  3. 把「地少了 N 个点」和别的事实连成因果：提示词禁止连因果；校验禁「事实里」「最要紧」这类说法。
  4. 坏棋只说「地少了」说不出原因：加「这手在周围几乎没起作用（第 1 线）」「AI 建议的点是给哪块棋长气 / 叫吃 / 提子」
     「对方哪一片原来能吃、这手之后活了」（相邻的块合成一片说）。
  5. 数归属翻转的点太少（损失散在一片）：按 9 个区域合计归属变化。
- 已知限制：
  - 讲得准的是「几口气、提几颗、哪片地少了、哪块棋原来能吃现在活了、这手没起作用」。「方向错了」「太缓」这类大局判断讲不出，只说「AI 建议下在 X」，让孩子点「看 AI 的下法」自己看。
  - 「哪块棋死了 / 危险」是 KataGo 归属判断（门槛 0.75 / 0.4），复杂对杀、劫争时可能不确定。
  - 数子结束时死子按归属判（≥ 0.6），没让孩子手动点死子。
