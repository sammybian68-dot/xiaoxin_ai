# 班级作业：小新每天自己去 QQ 群抓

女儿问「今天作业是什么」「上周二的作业」「最近一周的作业」，小新直接答，还在屏幕上出一张作业卡
（按天按学科、附图能点开翻）。答案来自提前抓好的作业库，不是现场去爬 QQ——现场爬要几分钟，还可能失败。

## 怎么跑

全在小新自己身上，不需要 Mac、不需要数据线。pad 放在孩子房间、连着家里 Wi‑Fi 就行。

| 在哪 | 做什么 |
|---|---|
| 小新服务（gpu2） | 定时器到点触发（`server/hw_schedule.py`），跑 agent（`server/hw_agent.py`）：调模型看截图决定下一步，校验、存库 |
| pad 上的小新 APK | 无障碍服务「小新 · 抓作业」（`AgentService.java`）：长轮询领动作，在 QQ 上点、滑、返回，截屏传回 |
| 两头之间 | `server/agent_bus.py`：一次一个动作，`GET /api/agent/next` 领、`POST /api/agent/done/<id>` 回 |

**pad 上要开一次辅助功能**：设置 → 辅助功能 → 已下载的应用 → 小新 · 抓作业 → 开。
小新的「设置 →作业」里能看到 pad 在不在线；在 pad 上打开设置页的话，没开会直接给个「去打开辅助功能」按钮。
开了以后 pad 熄屏、锁屏都没关系，抓的时候会自己点亮、过掉锁屏（这台没设锁屏密码；设了密码就过不去）。

## 什么时候抓、抓几次

女儿 18:00 开始写，所以 **18:00 截止**。10/15–11/3 三周的群聊里，每张「班级作业」分享卡的发布时间：

- 12 天里 11 天在 17:00 前发齐，大多 16:20–16:55；最晚一次是 10/23 语文 **17:32**。
- 最后到的通常是语文（张老师）。不是每天三科都有。

默认 **16:50 / 17:20 / 17:45** 各看一次，**每个时刻都跑，不是抓到就停**：

| 轮次 | 模式 | 做什么 |
|---|---|---|
| 今天一科都还没有 | full | 每一科都读 |
| 前几轮 | incremental | 告诉模型「已经存好了：语文、数学」，只读还没有的科目；再去群聊看有没有今天带【修改】的分享卡，有就重读那一科、标 revised。没新的几步就结束 |
| 最后一轮（17:45） | verify | 今天每一科都重读一遍交上来，**代码**和库里比（不让模型判断） |

存储按学科增量合并（`homework.merge_day`）：已有的科目不动，只补新的；标了 revised 或核对时代码判定改了，才替换那一科，作业卡上显示「已修改」。
为什么不整天覆盖：没改过的作业重读一遍是白花钱，重读还可能把读对的读错盖掉。

**怎么判断老师改没改**（`homework.changed_enough`）：去掉空白、标点、换行、全半角差异后，差的字数既超过 6 个、又超过较长那份的 12%，才算改了。
重读的误差一般只差个标点或一两个字（实测「4☆P52」读成「4⊕P52」），老师改作业是整句增删。
差两三个字（「32-33页」→「34-35页」）分不清是改了还是读错，**不动**——宁缺勿错。

**QQ 里修改长什么样**：三周里只有一次，10/15 语文。群聊里那张分享卡标题是「【修改】10月15日星期四语文作业」，
作业列表里还是同一张卡、标题不带【修改】、内容已经是改过的。所以列表读到的永远是最新版，看不出改过——
这就是为什么要去群聊看【修改】卡（便宜），最后一轮再全量核对兜底（老师改了但没重新分享）。

## 家长在哪看、在哪改

- **设置 →「作业」**：每天自动抓的开关、几点抓（可多选）、哪几天抓、一天最多试几次、
  用哪个模型看屏、一轮最多走几步、一天都没抓到要不要在群里说一句，以及「立即抓取当天」。
- **🔍 调试 →「作业」**：最近 20 轮跑了什么。点开一轮能一步步看它在 pad 上做了什么
  （动作、为什么、结果、那一步的屏幕小图）。抓不到时先看这里。

「立即抓取」是幂等的：今天已经抓到就直接回「今天已经抓过了，N 科」，不会重复跑；
连点两次只排一个队、正在抓时再点也不重复；pad 不在线就直接告诉你，不下单。定时器 5 秒内接手。

## agent 怎么抓

模型每一步先看当前屏幕截图，再决定下一步，动作只有这几个：
`look / tap / swipe / back / restart_qq / capture_image / save_day / finish`。

路径是 QQ 会话列表 → 群「勤惜2024级3班」→ 底部「作业」→ 全部作业列表（按日期从新到旧）。
定时器只抓当天；要补某一天或一段，管理员调 `POST /api/agent/grab {"day"} 或 {"since","until"}`（可带 mode），后台跑。
**从新到旧读，读完一天就 save_day 一天**：立刻校验、附图核验、按天写库（幂等）。中途断了不丢已存的日子。

为什么不写死点击流程：早先那版写死坐标的脚本（已删）实测五个坑——开屏广告吃掉点击、点进推送视频页、
中途锁屏、点到「宠物」、跨屏图裁成窄带。都不是「模型读不懂」，是脚本假设了界面状态。

为什么不用控件树：QQ 的作业列表和会话列表都是**自绘控件**，无障碍服务读控件树只能读到标题栏和
「最后一条消息」那行字，作业正文、日期、图片一个都读不到。所以正文只能看图读；
但每步会顺手读一次控件树，把能读到的带文字控件（比如底部那个「作业」按钮）连坐标给模型，有就优先用，点得更准。

## 宁缺勿错

错作业比没作业更糟——照着错的作业让孩子做，比小新说「我不知道」伤害大得多。所以：

- save_day 交上来的一天先校验：日期合法、不是未来、学科在册、正文非空且不是「（看不清）」、学科不重复。
  不合格**拒收**，让模型重读；重读还不行就这次失败，等下一次重试，**绝不写进库**。
- 附图入库前**另起一次看图核验**「这是不是一张完整的照片在全屏预览」，不是就丢掉；按内容去重；
  说属于某科、但那天没有这科作业的也丢掉。
- 有的科目作业整个就是一张图（数学老师常只发黑板照）：text 写「见附图：…」可以交，但必须真抓到图，否则拒收。
- 模型自己的疑虑（某个字看不清）放 `unsure` 字段，只存不显示——家长看到的是老师的作业，不是模型的批注。

## 数据

- `XIAOXIN_DATA/homework/<YYYY-MM-DD>.json`，一天一个文件，**按天幂等**（重抓覆盖那天）。永久留存。
- `XIAOXIN_DATA/homework/runs.jsonl`：每轮采集的记录（含逐步和小截图），留最近 60 轮。
- 接口：`GET /api/homework?date=|since=&until=`、`PUT /api/homework/<day>`（管理员）、
  `GET /api/homework/runs[?at=]`、`POST /api/homework/notify`、
  `GET|PUT /api/agent`、`POST /api/agent/run`、`POST /api/agent/claim`。
- 小新的工具：`homework_report`（`server/tools/homework.py`），说明在 `server/prompts/homework.md`。

## 踩过的坑

- 截图**原尺寸**给模型，它内部会自己缩，报回来的坐标差 7%，「作业」按钮连点 20 次都点在旁边空白上。
  → 统一缩到 1280 宽再给，点之前按**这一张的实际尺寸**换算回去。
- pad 抓到一半自己转成竖屏（QQ 点开图片预览会转），坐标按横屏算就全错。`wm user-rotation lock` 也锁不住
  （实测 49 张截图 43 张竖屏）。→ 不锁方向，每张截图按自己的尺寸换算。
- 锁屏判断：这台 Android 16 的 `dumpsys window policy` 里是 `mIsShowing=true`，不是旧版的 `keyguardShowing`。
  判错的那次 agent 在锁屏画面上白耗了 8 步。
- 抓之前先 `wake`：pad 平时熄屏，点亮、上划过锁屏（这台没设密码）。
- 退出二级页面**不要连按返回键**（会退出 QQ 跑到别的 app），用 `restart_qq`（回桌面、清任务栈重开 QQ）。
- QQ 列表里日期只写「11月3日」不带年份，模型会自己猜（实测猜成 2024、2025 都有）：提示里写明年份，
  存之前月日在范围里的按范围纠正年份。
- 只抓一天时，交完那天它还会往下翻（实测多走了 10 步去存 11/2 的图）：提示里写明「交完就 finish」，
  范围里的都存好了又读到更早的，直接回「调 finish」。
- 联想的内存清理（`ZuiMemoryCleaner_Recents`，在最近任务里一键清理也算）杀掉小新进程后，系统把「小新 · 抓作业」记成
  Crashed，**不再自动绑定**：设置里看着还是开着，其实 pad 再也不来领动作（11/4 17:48 被杀，11/5 三轮全空）。
  `dumpsys accessibility` 里 `Crashed services` 有它就是这个情况，关开一次辅助功能就好。
- 无障碍服务刚装好时系统可能报「process is bad」不绑定：先正常打开一次小新 app，再关开一次辅助功能。
- 历史里把动作写成「[动作] tap …」文字塞回去，模型会学着回文字不调工具。→ 用真的 tool_call / tool 消息。
- 一次 DNS 解析失败就把整轮丢了。→ 同一个模型等一等再试 4 次，再换下一个模型。
- 长跑要裁历史：留目标 + 最近 48 条，中间换成「已经存好哪几天」，tool_calls 和它的结果不能拆开。
- 一天里打转太久（10/15 那天图多，走了 30 多步）：走到 25 步提醒它「正文最重要，先交掉」。
- 代理有**每日额度**（$2000）。一次抓 25 天花了 2248 秒、179 张截图，把当天额度跑满了。
  每天只抓当天的话一轮十来步，成本小得多。
